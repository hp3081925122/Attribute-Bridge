# Attribute Bridge

版本 1.0.3。Minecraft 1.20.1 / Forge 47.4.23 / Java 17。仅桥接属性修饰符，不合并或修改基础值。

## 两种模式

| 模式 | A 的计算 | B 的计算 |
| --- | --- | --- |
| `replace`，目标为 B | 保留 A 的基础值，忽略该组所有来源对 A 的修饰符加成 | 使用 B 的基础值，应用 A、B 原有的修饰符 |
| `combine` | 使用 A 的基础值，应用 A、B 原有的修饰符 | 使用 B 的基础值，应用 A、B 原有的修饰符 |

例如 A 基础值为 10，带有 +2 修饰符；B 基础值为 20，带有 +3 修饰符。替换模式得到 A=10、B=25；合并模式得到 A=15、B=25。一个组可以包含两个或更多属性，替换模式只保留一个接收修饰符的目标。

三种原版修饰符运算保持不变：先计算 `ADDITION`，再计算 `MULTIPLY_BASE`，最后计算 `MULTIPLY_TOTAL`。百分比修饰符按接收属性的基础值参与计算，并遵守接收属性的数值范围。A 上的 +20% 转到 B 后，增加的实际数值可能改变。

替换模式不会彻底关闭 A 的基础行为；A 的基础值仍然存在。合并模式也不保证 A、B 最终值相同，因为双方基础值和数值范围可能不同。

## 配置

首次启动服务端或进入单人世界时生成以下两个文件。默认规则为空，需要配置实际属性 ID。客户端和服务端均须安装本模组，客户端自动接收服务端规则。单人游戏也使用服务端配置文件。

```text
config/attribute_bridge/
├── replace.json
└── combine.json
```

文件名决定模式，组内不再填写 `mode`。以下是 `replace.json` 的替换示例：

```json
{
  "schema_version": 1,
  "add_missing_attributes": false,
  "sync_attributes": true,
  "missing_attribute_policy": "error",
  "groups": [
    {
      "enabled": true,
      "name": "critical_chance_bridge",
      "attributes": {"mod_a:critical_chance": 0.5, "mod_b:critical_chance": 1.0},
      "target": "mod_b:critical_chance",
      "redirect_translation": true,
      "duplicate_policy": "keep_all"
    }
  ]
}
```

`combine.json` 的合成示例：

```json
{
  "schema_version": 1,
  "groups": [
    {
      "name": "other_critical_chance_bridge",
      "attributes": {"mod_c:critical_chance": 0.5, "mod_d:critical_chance": 2.0},
      "duplicate_policy": "keep_all"
    }
  ]
}
```

模组命名空间是占位示例，必须换成实际注册的属性。合成组不填写 `target`。一个属性在两个文件的所有启用组中只能出现一次；多个来源合并到同一目标时，将全部来源放进一个替换组。组名也须在两个文件间保持唯一，省略名称时自动按文件名编号。

`add_missing_attributes` 和 `sync_attributes` 是全局选项，可在任一文件填写；两份都填写时值须一致，只填写一份时另一份自动沿用。两份均省略时分别等于 `false` 和 `true`。`missing_attribute_policy` 可在每份文件分别指定。任一文件无效或两份规则冲突时，整次重载失败并保留旧规则。

升级时，若两个新文件都不存在且发现旧 `config/attribute_bridge.json`，会按原模式自动拆分。旧文件保留供恢复；两个新文件存在后，旧文件不再读取。已有其中一个新文件时，缺少的另一文件会自动生成为空规则。

- `add_missing_attributes`：默认 `false`，实体缺少组内任何属性时跳过整组，避免来源修饰符被屏蔽但无法转入目标。设为 `true` 后，访问组内缺失的属性时会给实体创建属性实例，基础值取该属性的注册默认值。其他模组的“实体是否拥有属性”判断可能因此发生变化。
- `sync_attributes`：默认 `true`，使组内属性通过原版属性数据包同步，保证客户端能够重算相同结果。已启用的同步标志在当前游戏进程中保持开启，避免回滚时覆盖其他模组设置；可能增加这些属性的同步流量。设为 `false` 后，仅适用于不依赖客户端属性计算且已自行处理同步的场景。
- `missing_attribute_policy`：`error` 遇到未注册属性时拒绝整份新配置并保留旧规则；`skip_group` 只跳过含有未注册属性的整组，记录英文警告。该选项适合不同实例安装不同可选属性模组的情况。
- `duplicate_policy`：默认 `keep_all`，不同原属性下的相同 UUID 仍分别贡献一次；`prefer_self` 按 UUID 去重，优先保留接收属性自身的修饰符，其次按 `attributes` 顺序取第一份。去重跨越全部运算类型。
- `redirect_translation`：默认 `true`，替换模式下读取来源属性的翻译键时，返回目标属性的翻译键；设为 `false` 保留来源属性的名称。合并模式始终保留各自名称。旧配置无需增加此字段即可启用名称替换。
- `enabled`：设为 `false` 可停用该组；停用示例中的属性不会进行注册表解析。

每份文件最大 64 KiB，合并后的同步配置也不得超过 64 KiB；两个文件合计最多 256 组，每组最多 64 个属性。常见的二至八属性组开销较低；很大的组在来源频繁改变时，会增加关联缓存刷新和修饰符合并成本。

## 管理命令

以下命令需要权限等级 2：

```text
/attributebridge reload
/attributebridge list
/attributebridge inspect @s minecraft:generic.armor
```

`reload` 重新读取规则、刷新现有实体属性缓存并通知在线客户端。`inspect` 显示基础值、最终生效值、原生修饰符数量以及计算时实际采用的修饰符。它支持检查任何已注册且目标拥有的属性。

## 兼容方式与边界

修饰符保存在其原属性中，计算时才组合。装备、药水、命令、持久修饰符和使用标准 `AttributeInstance` API 的模组都沿用原来的添加、替换和删除路径；不会生成额外的持久副本，因此正常存档、重进和卸载本模组后不会残留桥接修饰符。

`getBaseValue()` 和 `getModifiers()` 继续返回原生数据，写入与 UUID 删除也操作原属性。标准 `getValue()` 和实体的属性最终值查询使用桥接结果；管理员可通过 `inspect` 对照生效结果。

替换模式默认重定向 `Attribute.getDescriptionId()`：A 替换为 B 后，物品 tooltip 等通过该方法获取属性名称的位置会显示 B 的译名，并跟随游戏语言切换。注册 ID、修饰符存储和数值算法保持原样；tooltip 仍按原修饰符条目显示，可能出现多行同名属性。名称替换按全局规则生效，不依赖某个实体是否具有组内全部属性。写死翻译键、缓存了旧名称或覆盖该方法且不调用父类的模组需要单独适配。

名称规则随服务端规则同步并支持 `/attributebridge reload`；客户端退出连接后恢复原始名称。客户端和服务端须一起升级至 1.0.3 或使用相同网络协议的后续版本。

直接自行计算修饰符、缓存旧结果、读取私有字段或覆盖原版属性计算的模组可能绕开桥接，需要针对该模组核对源码。相同 UUID 同时出现在双方属性中时，是否重复计入由 `duplicate_policy` 决定。属性拥有不同单位或不同玩法含义时，应由整合包作者自行确认转换是否合理。

## 构建与检查

```powershell
.\gradlew.bat build --no-daemon
```

自动检查覆盖修饰符 UUID 冲突策略、跨运算去重、删除后重算、配置错误拒绝、禁用组与配置同步格式。Mixin 注解处理器验证目标方法和映射。游戏内仍应检查装备卸下、药水结束、重进世界、规则热重载、服务器客户端属性一致性等行为。名称替换需检查装备和药水提示、切换中英文、关闭 `redirect_translation` 后热重载、将规则移到合成文件并删除 `target`，以及断开连接后原始名称恢复。

## 按比例转换

`attributes` 使用对象：键为属性 ID，值为该属性向其他属性输出修饰符的倍率。倍率须是有限、非负数；`1` 为原值，`0.5` 为一半，`2` 为两倍，`0` 为不输出。自身修饰符不乘倍率。旧数组格式继续兼容，视为所有倍率均为 `1`。

替换模式 A 倍率 `0.5`、目标 B 倍率 `1`：A 的 `+10` 转到 B 后为 `+5`，B 自身修饰符保持原值。A 自身不再应用修饰符；目标 B 的倍率在此模式下不参与转换。

合成模式 A 倍率 `0.5`、B 倍率 `2`：A 保留自身修饰符并接收 B 修饰符的两倍；B 保留自身修饰符并接收 A 修饰符的一半。三种运算类型与 UUID 保持不变，百分比按修饰符 amount 缩放：`+20%` 乘 `0.5` 后为 `+10%`。不对属性最终值或基础值进行比例转换，也不会反复叠乘已桥接结果。

倍率不改变属性名称重定向；物品提示仍显示原始修饰符条目的数值，不保证显示按倍率转换后的数值。很大倍率可能使最终属性触及其数值范围上限。
